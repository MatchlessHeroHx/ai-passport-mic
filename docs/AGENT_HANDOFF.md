## Product behavior

- OK PRESS starts or stops dictation. While ready, UP PRESS sends Command-Z and
  DOWN PRESS sends Return; both are ignored while offline, starting or recording.
- Screen power (`main/mic_screen.c`):
  - The screen dims to 5% after 15 s with no key press or state change, and turns
    off after 45 s. Full brightness is 70%.
  - Starting, recording and pairing hold it on, and any model state change lights
    it again.
  - While dimmed every key works as usual. While off, OK lights the screen and
    starts dictation; UP/DOWN only light it and send nothing.
- The board has no firmware-controllable LED. All GPIOs are used by the display,
  keys, I2C and audio; the "recording light" in the copy is a drawn dot.
- BLE uses LE Secure Connections with bonding and a six-digit passkey. A merged
  flash wipes the device bond. On `CBErrorDomain Code=14 Peer removed pairing
  information`, forget Passport Mic in macOS Bluetooth settings and pair again.
- Audio: 16 kHz mono, one 164-byte IMA ADPCM block per 20 ms, played into
  BlackHole 2ch. Chatterfly must use BlackHole 2ch as its microphone.
- Wired fallback: `.venv/bin/python companion/passport_mic.py --transport usb`.
- Power key (separate hardware button): hold about 0.5 s to power on and about
  2 s to power off; it cannot restart the device.
- UI layout:
  - A 240 × 240 video companion, Xiao Sheng, with idle, listen and nod clips.
  - A speech bubble with short lines.
  - A three-row bottom card.
  - A link pill (Bluetooth or USB icon plus words) at top left, and battery at
    top right.
- All UI copy is in `docs/firmware-copy.zh_CN.md`, the owner's revised final
  copy and the source of truth.

## Non-obvious design decisions

1. Synthetic Return and Command-Z go to `.cgSessionEventTap`. The HID level is
   avoided because the input methods' HID-level event taps (WeType, Chatterfly)
   swallow synthetic edit keys there. The right-Control dictation toggle still
   posts at the HID level, which works. Keep this split in
   `companion/chatterfly_key.swift`.
2. Under radio congestion the firmware drops whole frames instead of stalling.
   - Audio and the periodic HELLO are skipped when free NimBLE msys blocks fall
     below a reserve of 6, keeping room for the Mac's control-write responses.
   - Key and START/STOP frames retry for up to 150 ms.
   - Only a lost link takes the device offline (`send_frame` in
     `main/mic_app.c`, `mic_ble_send` in `main/mic_ble.c`).
   - `CONFIG_BT_NIMBLE_MSYS_1_BLOCK_COUNT=24` in `sdkconfig.defaults`.
3. Host commands (`P` ping, `A` start ack, `X` reset) are an atomic bitmask, so
   a busy loop never makes the device reject Mac writes. `X` overrides earlier
   bits in the same write.
4. The bridge fills gaps of up to 25 frames with silence and logs a
   "frames lost, silence filled" line, then ignores UP/DOWN until the next HELLO.
   - Larger gaps, corrupt fragments, queue overflow, stale audio and 4 failed
     heartbeats in a row end the session as `LinkLost`, and the bridge
     reconnects. Every `LinkLost` carries a reason.
   - Control writes retry 3 times, 50 ms apart.
   - Only pairing, authentication and permission errors (`needs_user`) exit.
5. The video is a tile pack. Never hand-edit it.
   - `assets/images/mic_clips.bin`: about 4.9 MB, 6 fps, uncompressed RGB565,
     16 × 16 tiles. It is embedded with `EMBED_FILES`.
   - `tools/generate_mic_clips.py` builds it from `VIDEO/`, using ffmpeg, OpenCV
     and numpy from the system `python3`, not `.venv`. Change clip ranges there.
   - The owner chose clarity over smoothness.
   - The listen video is split into lead-in, loop and return. Loops ping-pong,
     and one-shot clips hand back to idle on the closest matching frame.
   - `main/mic_ui.c` draws tiles straight from flash and redraws only changed
     tiles. Every LVGL setter invalidates, so set values only on change.
6. Bubble lines live in `main/mic_lines.c`, grouped by state.
   - A line never repeats back to back, and a line equal to the current title or
     caption is skipped.
   - The just-connected greeting stays about four seconds.
   - After changing any Chinese text in `main/mic_ui.c` or `main/mic_lines.c`,
     rerun `tools/generate_mic_font.py`.
   - The host render checks every line's glyph coverage and a 196-pixel width
     limit.
7. Screen off is reversible, not panel sleep, following
   `docs/reference/shinku-chen/ble-active-idle-power.md`.
   - Off is backlight 0 plus DISPOFF (`bsp_display_set_on(false)`), which keeps
     the frame memory. Sleep In stays reserved for the deep-sleep path.
   - While off, `mic_app.c` skips `mic_ui_update`, so the video and LVGL stop
     redrawing.
   - Waking runs `lv_refr_now` first, then DISPON, then the backlight, so no stale
     frame flashes.
   - The timing logic is pure C in `main/mic_screen.c` with host tests; the
     thresholds are `MIC_SCREEN_DIM_MS` and `MIC_SCREEN_OFF_MS`, and the levels
     are `BACKLIGHT_ON` and `BACKLIGHT_DIM` in `main/mic_app.c`.
   - Key handling goes through `mic_screen_key` before any action. It wakes the
     screen and returns false only for UP/DOWN while off.

## Power saving

Done: dim and off stages for the screen. Not measured; the device can only report
CW2017 SOC and voltage, so compare SOC over an hour of idle.

Candidates, in order of expected benefit:
1. Suspend the ES8311 while idle. `main/mic_app.c` reads I2S every 20 ms even
   when not recording, and keeps doing so while the screen is off.
   `bsp_audio_sleep()` and `bsp_audio_wake()` exist. Waking must finish before
   START; measure the added start latency.
2. Deep sleep after a long offline period, waking on any key (GPIO0 low). Reuse
   the sequence in `main/demo_low_power.c` and the wake guard in
   `main/key_guard.h`. The device restarts and reconnects with the bond. Never
   do this while connected.
3. `CONFIG_PM_ENABLE` with DFS only (CPU down to 40 MHz when idle). The reference
   doc above reports it is safe with an active BLE link. Automatic light sleep
   (`light_sleep_enable`) drops the link, so do not enable it.
4. BLE connection latency while idle. The user said to leave this for now.
